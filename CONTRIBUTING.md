# Contributing to VAI DataSystem Phase Two

## Development Guidelines

### Branch Strategy
This is an independent Phase Two development fork. All development should follow these guidelines:

#### Branch Naming Convention
- `feature/feature-name` - New features
- `bugfix/issue-description` - Bug fixes
- `admin/dashboard-component` - Admin dashboard related work
- `mobile/ui-improvement` - Mobile app enhancements

#### Development Workflow
1. Create feature branches from `main`
2. Work on your feature branch
3. Test thoroughly before merging
4. Create pull requests for code review within the team
5. **Pull requests should be sent to Phase Two Repo**

### Repository Relationship
- **Original Repo**: [iden-a/VAI-DataSystem](https://github.com/iden-a/VAI-DataSystem) (Core reference point)
- **Phase Two Repo**: [BreatheRight/VAI-DataSystem-PhaseTwo](https://github.com/BreatheRight/VAI-DataSystem-PhaseTwo) (Active development)

This fork maintains attribution to the original work while operating independently for Phase Two development.

### Code Standards
- Follow existing code style and patterns
- Write meaningful commit messages
- Include comments for complex logic
- Test new features before committing
- Update documentation as needed
